# Four-token compute and read overlap

Keep the mixed reference artifact, native arithmetic, CLOCK 1,460-slot cache,
12GiB total budget, 8,192-token allocation and exact 72-token prime plus sixteen
continuation inputs used by the completed capacity screen. Include all four
blocks. This is a diagnostic stage, not a throughput comparison or promotion.

Run two fresh developer binaries in order: existing-command profiling, then
per-dispatch timestamp profiling. Model and harness copies add observation only;
production source and binary remain unchanged. No kernel or submission policy
changes. Prime profiling is disabled. Existing deterministic priming and full
checkpoint, acceptance and state evidence remain present.

Each completed block drains normally, then exports its complete command profile
and all 48 expert dependencies before clearing the bounded capture. Capture
actual expert row counts: a four-token input does not mean every expert sees four
rows. Bound each block to 20,000 operations and a 32MiB serialized file. Reserve
an additional conservative 512MiB within the same 12GiB admission for profiling
metadata, serialization and counter buffers. Check physical memory including
peaks and after model destruction.

Before each model process, run the native power/thermal preflight. Stop on an
admission failure, non-nominal thermal state, Low Power Mode, observed compression,
decompression growth or changing swap. Use the existing exclusive GPU lease.
Each process is bounded to 150 seconds and the whole stage to 360 seconds.
Do not pool disturbed or unfinished attempts.

Match complete vocabulary logits, routes, persistent state, initial cache and
workspace geometry against the same-capacity sealed untraced reference. Validate
all command timestamps, leases through GPU completion, unique selected experts,
complete top-ten routes and all native command/dispatch counters. Cross-check
the operation/shape population between profiling modes.

Partition command capture into exclusive overlap buckets, preserving mixed
command classes. Keep dispatch timings separate: per-pass instrumentation changes
execution cost and cannot establish normal throughput or attainable savings.
Use the completed evidence to select one subsequent actual-input experiment;
do not repeat rejected cache hypotheses or assume one-token results transfer.
Kernel selection is a reviewed follow-up decision, not an automatic threshold
over the largest duration. No real draft performance or acceptance is measured.
